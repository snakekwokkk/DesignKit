# 团队整理规则

本文件保存可复用的偏好与判断方法。沿用目标项目的已确认规范；下列命名是默认候选，不要求每个项目创建所有分类或数值。

## 从实际设计反推基础颜色

- 先提取并聚类已有颜色，识别品牌锚点、状态色、中性色及独立模块色；记录原值与用途。
- 色阶服务实际设计。可按项目需要补全色阶，但不要为了整齐把已确认锚点强行塞进等距十色阶。不同来源的蓝色可能有色相差异；明显不连续时展示原色、候选色及应用对比，提出保留、归一或独立处理的建议。
- 一次性装饰色不自动升级成全局基础色；重复且有独立调色需求的色值可保留。扩展色不等于有问题，但应解释使用位置与保留原因。
- 黑白可归入灰色的两端，减少仅两项且没有独立意义的分类。纯黑是否保留取决于实际与预留需求，不因某个项目不用就永久禁用。
- 透明颜色不是更高一层“色阶”。少量局部装饰透明度可留在样式；反复使用且有明确用途的透明色可以是专用变量。不可只为消除透明度而偷偷换成实色。

## 语义按用途区分

通常采用一层分组加清楚名字：文字、图标、背景、描边、图表、控件；重要且有独立视觉身份的模块可以单列，如 AI。避免只有一两项的第三层子分组。

不同角色即便当前映射同一基础色也可保留，例如文字与图标；相同用途、相同表现且没有独立变化理由才适合合并。基础色有 7 个、语义有 9 个本身不是问题。

| 类别 | 候选命名与边界 |
| --- | --- |
| 文字 | 主要、次要、品牌强调、反向、错误、警告、成功。颜色表达信息重要程度/状态；字号与标题层级交给文字样式。不要为每个业务数字单建文字颜色。 |
| 图标 | 主要、次要、品牌强调、反向、错误、警告、成功。纯装饰圆点不因它被画成图标就必须表达状态；装饰分类点可复用通用角色，独立模块装饰放模块内。 |
| 背景 | 页面、卡片、次级、品牌强调、品牌浅色、信息提示、状态浅色等，名称说明用途与强弱。图标的底色仍属背景用途。 |
| 描边 | 默认、分割线、品牌强调、错误、警告、成功、反向。不要保留两个表现和用途都相同、只靠“弱化”区分的重复项。 |
| 图表 | 品牌强调、红色、黄色、绿色、辅助线、标记填充等。通用图表色不绑定“评分”业务；系列色与风险等级意义不同，使用说明必须区分。新市场颜色变动后复核名称是否仍准确。 |
| 控件 | 当前只有轮播也可保留分类，便于以后真实出现的按钮、输入框。是否拆分组件级 token 取决于实际状态和独立调整需求，不预建全部状态。 |
| 独立模块 | 按具体用途命名，如正文文字、建议标题文字、卡片描边、装饰主色、装饰点缀、建议序号。相同底色不同角色可独立调节，避免只用“蓝色1/2”作为语义名。 |

警告、错误等色阶不规定固定编号。结合背景、实际字号、可读性和品牌意图提出建议；已有用户选择优先，如要求亮黄色就不擅自换深棕色。存在可读性问题时说明具体场景并给替代，而不是无条件宣布整套配色不合格。

## 多市场与固定视觉模块

- 若多个基础色族都可能随市场调整，优先在同一个 Color Primitives 集合配置市场模式；语义别名可以保持不变，让被引用基础变量按所在容器继承的市场模式解析。
- 模式由对象的显式设置及祖先继承决定，Frame 名称不会自动识别国家。文档用简单例子解释 Auto 是继承，不额外创建多层演示容器使用户困惑。
- 只需要品牌变化且现有结构已拆分时，也可保留独立品牌集合，不为套模板强迁移。
- 跨市场固定的模块采用固定基础变量：同一集合各市场模式填相同值，或已有独立单模式集合。模块语义引用这些固定变量，不再间接引用可变品牌/灰色/状态色。
- 固定要求应覆盖正文、标题、编号、装饰、描边、渐变等实际角色，不能只锁背景。不要直接把模块根节点强制成某个国家模式来掩盖错误引用。

## 排印与数字基础

- 字体家族、字重、字号、行高等为基础变量；完整字体组合为文字样式。不把纯颜色层级与字体层级混在一起。
- 以设计师和开发日常语言命名。可用：标题/一级、二级、三级；字段/姓名、名称、内容；正文/普通、大号、加粗；标签/普通、提示；数字/小号、中号、大号。根据项目删减或扩展。
- 用户姓名是资料角色，不因它最醒目就命名“主标题”。同类资料内容放一起。避免只写“区块、紧凑、辅助、标准”而没有可理解边界。
- 规格相同且用途相同的样式合并；标题与强调正文即便暂时同规格，若职责不同且会独立演进可保留。
- 不预设统一最小字号。用户要求提升某些字号时迁移实际使用与样式，再删除旧变量；字号和行高分开处理，不能顺手更改未授权的行高。
- 正文混合字重/颜色/链接需保留区间。刻度和数据标签能否共用样式依实际规格与用途判断。
- 字重样式名与数值绑定冲突时检查实际字体支持与最终解析，不能只改显示名。

## 圆角、间距、描边和渐变

- 以已有分布提出收敛方案，保留具有实际区分的值。近似小数只有用户允许归一才调整。
- full 可用于胶囊/圆形，是否保留按项目；0 可直接用数值，除非有模式切换或代码约定等变量化理由。
- 间距包含布局 gap 与 padding，但不把所有坐标、宽高都当作间距。不要为凑统一数列改变插图结构。
- 描边粗细按实际通用宽度建基础变量；可按用户要求增加有说明的预留宽度。仪表盘数据弧线、原生图标线条不强制归入通用边框宽度。
- 完整渐变保存样式。需要主题联动的色标用语义变量，固定装饰渐变留固定值；不为每个渐变色标都强建基础变量。

## 描述与同事交付

描述示例：

> 用途：默认标题、重要资料值及主要信息数字。当前示例：综合评分标题、身份证号、主评分数字。边界：次要说明用“文字/次要”；品牌交互文字用“文字/品牌强调”；AI 专用内容使用 AI 对应变量。

描述以当前实际名称、映射及位置为准。新增/改名/合并/改用途/改引用后同步更新，不能只在聊天里解释。预留项写明“预留、尚未使用”及预期用途；范围内未使用不写成全文件未使用。Token JSON 保留 `$description`。

同事延展时需要知道：默认用什么、什么时候换另一项、哪些固定不随市场变、缺少规范如何新增。以具体例子解释，避免只交付色板和抽象术语。
