# Figma 关联、清理和验证

本文件补充设计系统整理中容易损坏现有稿件的操作。实际 API 和调用约定以当前 Figma 工具指引为准；这里不保存工具版本、文件 key、节点 ID 或历史会话。

## 发现与变更记录

- 使用当前活跃变量/集合/样式库存判定对象是否存在。按 ID 查询有时可能返回已删除对象的残留信息；不能据此断言仍有效。
- 用集合、模式、变量名称与 ID 建索引；已有名字相同但类型、用途或集合不同，不能直接覆盖。
- 大范围发现先返回 ID、类型、名称和计数，再针对具体对象读属性。不要把所有页面、所有变量 valuesByMode、所有图层填充一次返回。
- 每个调用显式设置目标页面；遵循当前工具的页面加载、上下文和返回限制。保存完整明细到工作目录，返回摘要与定位，不丢失需要复核的数据。
- 相关改动按可安全重试的批次执行；共享集合的写操作避免相互竞争。记录原始值、绑定、样式 ID、变更目标及受影响 ID，使中断后能先读状态再恢复。
- 不在 Frame/Instance 等不支持的对象上写 description；变量和样式用其支持的说明字段，其他记录放外部状态文件。

## 变量与主题

- 创建时设置与用途匹配的 scopes，减少所有选择器出现全部变量。基础色的范围可以覆盖其实际需要的用途，语义层尽量精确。
- 检查变量类型、别名目标、所属集合与模式；递归解析别名并检查循环。基础与语义数量不必一一对应。
- 不根据 Frame 的名字设定模式。检查显式模式、祖先继承和默认模式；测试时保留原始设置。
- 字体家族变量变化前加载相关模式所需字体；根据当前 API 能力处理变量对文字样式的绑定。
- 小数用合理误差比较，如 1.4 可能读取为 1.399999976；业务上不同的近似值不能以大容差悄悄合并。
- 变量命名字符限制依据当前 API。若 1.4 不能直接入名称，采用有效名称如 `strokeWidth/1_4`，在说明与导出里明确实际值 1.4。

## 文字、混排与布局

- 修改文字前枚举实际区间字体并加载，不能假设全节点只有一种字体。
- 读取并保留 textStyleId、区间样式、字体、字号、字重、行高单位、颜色与变量绑定。修改某些排印属性或绑定可能清掉样式 ID，写后验证并在兼容时恢复正确样式关联。
- 迁移字号/行高应同时处理样式、直接值、区间覆盖及变量引用；一个层面迁移不代表全部完成。
- 变大文字后检查祖先容器。子卡片 HUG 不代表轮播行/外层 Frame 也 HUG；固定高度的祖先即使 clipContent 关闭也可能覆盖后续内容。
- 检查 AI 等模块的绝对定位背景是否与外壳同高、同起点、拉伸约束匹配。只修复本次变化引发的问题，不擅自重排整张设计稿。

## 颜色、透明度和渐变

- 区分图层 opacity、paint opacity、颜色变量 alpha 与渐变色标 alpha；保持最终渲染与目标一致。图层 100% 不代表每层填充不透明。
- 只解绑过时或不适用的 opacity 绑定时，保留当前渲染数值；不要误将存为 100 的值写到只接受 0–1 的属性。
- fills/strokes 等数组 clone 后重赋值；变量 paint helper 返回新 paint 时必须接住并应用。
- 基于当前 API 能力给渐变色标绑定变量，保留渐变类型、方向变换、位置、alpha、可见性与混合模式。
- 特别验证白色到透明等渐变：把不透明颜色变量绑定到透明色标可能将 alpha 重置成 1。若当前 API 不能保留独立透明度，让透明端固定，或按明确需求建透明变量；不能留下全白结果。
- 绑定纯色前核对叠加的多层填充；清理重复白底只在确认目标角色与视觉影响后做。
- 图片内部颜色不算已建立可编辑绑定，区别“保持图片不变”与“所有颜色已变量化”。

## 描边及清理

- 单一 strokeWeight 绑定可能在读取时展开为四边属性；验证每条实际边。非对称边分别处理，不抹平原差异。
- 仪表盘弧线宽、图标矢量笔画与通用容器描边分开检查；不能把相似数值一网打尽。
- 删除旧变量前检查语义别名、节点直接引用、样式、字符区间、渐变色标及其他支持的绑定。删除样式前检查节点/区间使用。
- 范围外引用无法核实或存在旧页保留要求时，保持文件级资源，不以“本次没有用到”为由删除。可以标注暂保留及原因。
- 重命名同一角色优先保留 ID；合并时先迁移引用再删除源。样式跨分组改名和组内排序分开操作，不能假定排序 API 支持跨目录。

## 完成证据

变更结果至少能回答：创建/修改了哪些对象；绑定了哪些属性；哪些项目尚未决；是否有预留或范围外未核实项。用简短汇总给用户，完整记录落盘。

- 结构：活跃对象数量、名称、类型、作用范围、主题模式、别名和绑定完整。
- 外观：涉及视觉变化的代表区域截图；多市场模块按相同状态比较，检查固定模块一致、主题区域按预期变化。
- 排印/布局：原有混排保留，无新溢出、遮挡、背景尺寸不匹配；字体缺失不被静默替代。
- 导出：JSON 可解析，描述与当前 Figma 一致，别名可解析，模式无遗漏；自定义元数据与消费端格式明确区分。
- 幂等：再次盘点后没有计划外重复变量或样式，也没有悬空引用。已有证据充分时无需为了“第二遍”再执行全部写操作。

只做名称/描述等元数据变化且能证明字体、绘制和布局未变时，以结构证据验证即可。不要把“脚本校验通过”写成“已完成真机验证”或“已验证所有文件”。
