# DesignKit

<img src="assets/designkit-compass-icon-400.png" alt="DesignKit 黄色圆规图标" width="120" />

从已有 Figma 设计稿建立并维护设计系统的 Codex Skill。

适合先完成代表性页面、确定风格，再建立规范并交给同事延展的工作方式。既支持首次建立，也支持已有系统检查、新页面纳入和多市场主题扩展。

## 能做什么

- 盘点实际使用的颜色、字体、圆角、间距、描边和渐变，定位重复与遗漏。
- 创建或更新基础变量、语义变量和主题模式。
- 整理文字与渐变样式，并关联设计稿中的图层及文字区间。
- 区分需要随主题变化的内容与跨市场固定的模块。
- 同步变量描述，补齐用途、当前示例及使用边界。
- 检查关联、模式、混排和布局，导出保留说明及主题关系的 Token JSON。

Skill 包含可复用的规则与操作指引，实际 Figma 操作由 Codex 配合可读写 Figma 的连接工具完成；安装此 Skill 不会自动取得文件权限。

## 安装

将本仓库下载到本机 Codex 的 Skills 目录，文件夹命名为 `designkit`。默认目录为 `~/.codex/skills/designkit`。

也可以使用：

```sh
git clone https://github.com/snakekwokkk/DesignKit.git ~/.codex/skills/designkit
```

如果已安装同名 Skill，先保留原有版本，再按自己的更新方式替换，避免覆盖自定义规则。

## 使用

向 Codex 提供 Figma 链接和需要整理的页面或 Frame：

> 使用 $designkit，整理这个文件的「设计稿」页面，创建并关联变量与样式，集中列出需要我判断的项目。

也可以只检查某一类别：

> 使用 $designkit 检查这些 Frame 的文字样式，只给检查结果、使用位置和整理建议，暂时不修改。

## 工作流程

1. 确定范围与项目要求，读取已有规范。
2. 盘点实际使用，记录具体位置和绑定关系。
3. 提出整理方案：明确且已授权的操作直接执行，涉及设计判断的项目集中给出建议。
4. 创建或更新变量、模式及样式，关联现有设计稿。
5. 同步描述，检查视觉、布局和引用；仅清理能够确认无用的项目。
6. 交付文件内的设计系统、Token JSON、样式使用说明及待判断清单。

后续新增页面时优先复用已有系统，只补充确实缺少的内容。

## 规则与边界

- 尊重指定范围，不擅自整理历史稿或示意内容。
- 保留设计稿的重要配色，不为凑色阶直接改变设计意图。
- 结合用途判断合并，不能因为色值相同就删掉不同职责的语义变量。
- 具体色值、字号、圆角和市场配置由项目决定。
- 每次调整语义名称、用途或映射，同步更新 description 和导出中的 `$description`。
- 部分设计稿建立的是已验证的初版系统，不预建所有未来组件与状态。
- 仅要求检查时不修改文件；不会自动发布组件库、上传 GitHub 或通知同事。
